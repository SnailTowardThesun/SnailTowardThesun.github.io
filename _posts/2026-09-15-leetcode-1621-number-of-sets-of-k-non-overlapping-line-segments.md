> 不重叠区间计数与任务调度、资源分配问题同源；本题还暗藏「隔板法」组合模型，答案恰好等价于组合数 C(n+k-1, 2k)。

## 题目

LeetCode 1621. Number of Sets of K Non-Overlapping Line Segments（大小为 K 的不重叠线段的数目）

Difficulty: **Hard**

给你一维空间的 `n` 个点，编号从 `0` 到 `n-1`。请你找到并返回画 `k` 条互不重叠线段的方案数。

- 每条线段包含两个端点，且两个端点不能是同一个点。
- 线段之间不能有公共部分，但允许首尾相接，即相邻两条线段**可以共享一个端点**。
- 答案对 `10^9 + 7` 取余。

### 示例

```
示例 1：
输入：n = 4, k = 2
输出：5

示例 2：
输入：n = 3, k = 1
输出：3
解释：3 个点之间可画 [0,1]、[1,2]、[0,2] 共 3 条线段。

示例 3：
输入：n = 3, k = 2
输出：1
解释：只能画 [0,1] 和 [1,2]，两条线段共享端点 1，题目允许。
```

## 解题思路

### 状态定义

设：

```
dp[i][j] = 只使用编号 0~i 的点，画出 j 条互不重叠线段的方案数
```

注意点 `i` 可以不被任何线段使用。按「最右端点 i 是否参与」分类：

1. **点 i 不参与任何线段**：j 条线段全部画在 0~i-1 上，方案数为 `dp[i-1][j]`。
2. **点 i 是最后一条线段的右端点**：设最后一条线段为 `[t, i]`（t < i），其左侧的 j-1 条线段只使用 0~t 的点。因为允许共享端点，左侧方案数正好是 `dp[t][j-1]`。对所有可能的 t 求和。

于是得到基础转移：

```
dp[i][j] = dp[i-1][j] + Σ dp[t][j-1]   (t = 0..i-1)
```

直接维护这个求和需要 O(n²k)。

### 消去求和：两式相减

把 `i` 和 `i-1` 的展开式并排写出：

```
dp[i][j]   = dp[i-1][j] + Σ dp[t][j-1]   (t = 0..i-1)
dp[i-1][j] = dp[i-2][j] + Σ dp[t][j-1]   (t = 0..i-2)
```

两式相减，求和项被消掉，只剩 `dp[i-1][j-1]` 一项：

```
dp[i][j] = 2 * dp[i-1][j] + dp[i-1][j-1] - dp[i-2][j]
```

转移降为 O(1)，整体复杂度 O(nk)。

### 边界与取模

- `dp[i][0] = 1`：画 0 条线段只有「空方案」一种。
- `i < j` 时点不够画出 j 条线段，方案数为 0，dp 表初值天然覆盖，内层循环从 `i = j` 开始即可。
- `i < 2` 时 `dp[i-2][j]` 越界，视为 0。
- 转移含减法，取模后可能为负，需要加回 mod 修正。

### 手算 n = 4, k = 2

| dp[i][j] | j=0 | j=1 | j=2 |
|----------|-----|-----|-----|
| i=0 | 1 | 0 | 0 |
| i=1 | 1 | 1 | 0 |
| i=2 | 1 | 3 | 1 |
| i=3 | 1 | 6 | **5** |

答案 `dp[3][2] = 5`，与样例一致。

### 扩展：组合数视角

「允许共享端点」经过「在点之间插入 k-1 个虚拟分隔点」的经典变换后，本题答案等价于从 `n+k-1` 个位置中选 `2k` 个端点：

```
answer = C(n+k-1, 2k)
```

代入样例：C(5,4)=5、C(3,2)=3、C(4,4)=1，全部吻合。预处理阶乘与逆元即可 O(n+k) 求解，可作为 DP 之外的对照写法。

### 复杂度分析

- **时间复杂度**：O(nk)，每个状态一次 O(1) 转移。
- **空间复杂度**：O(nk)；转移只依赖上一行与本行前一个状态，可用滚动数组优化到 O(n)。

## 代码实现

{% raw %}
```cpp
class Solution {
   public:
    int numberOfSets(int n, int k) {
        const int mod = 1000000007;
        // dp[i][j]：只使用点 0~i 画 j 条互不重叠线段的方案数
        vector<vector<long long>> dp(n, vector<long long>(k + 1, 0));

        // 边界：画 0 条线段只有一种方案
        for (auto i = 0; i < n; i++) {
            dp[i][0] = 1;
        }

        for (int j = 1; j <= k; j++) {
            // i < j 时点不够，方案数为 0，直接从 i = j 开始枚举
            for (int i = j; i < n; i++) {
                long long option1 = dp[i - 1][j];
                long long option2 = dp[i - 1][j - 1];
                long long option3 = (i >= 2) ? dp[i - 2][j] : 0;

                // 转移：dp[i][j] = 2*dp[i-1][j] + dp[i-1][j-1] - dp[i-2][j]
                long long res = (2 * option1 + option2 - option3) % mod;
                // 修正减法可能导致的负数取模
                res = res < 0 ? res + mod : res;
                dp[i][j] = res;
            }
        }

        return dp[n - 1][k];
    }
};
```
{% endraw %}

### 代码解析

- 用 `long long` 存状态：`2 * option1` 在取模前最大约 2×10⁹，超出 int 表示范围，必须用 64 位整数。
- 内层循环从 `i = j` 起步，跳过 `i < j` 等恒为 0 的状态，减少无效计算。
- 负数修正只做一次 `+ mod`：参与运算的三项都在 `[0, mod)` 内，表达式最小值约为 `-mod`，加一次即可回到非负区间。

    EXPECT_EQ(s.numberOfSets(3, 2), 1);

## 总结

这道 Hard 题的 DP 状态本身不难想到（按最右端点分类），真正的考点是把 O(n²k) 的求和转移通过「相邻两式相减」压缩成 O(nk) 的常数转移——这是计数 DP 中处理前缀和型转移的通用技巧。实现时还要留意两个细节：`2×dp` 需要 `long long` 防溢出、含减法的取模要修正负数。理解到位后再回看组合数公式 C(n+k-1, 2k)，会发现 DP 与隔板法只是同一计数对象的两种表达。
