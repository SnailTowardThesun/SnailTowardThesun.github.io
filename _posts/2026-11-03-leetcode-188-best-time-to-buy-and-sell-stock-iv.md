> 188 是股票系列的终极形态：至多 k 笔用 buy[i][j]/sell[i][j] 两排状态即可统一 121/123/122；当 k ≥ n/2 时交易次数不再受限，贪心拼出所有上坡就是最优解。

## 题目

LeetCode 188. Best Time to Buy and Sell Stock IV（买卖股票的最佳时机 IV）

Difficulty: **Hard**

给定一个整数 `k` 和一个数组 `prices`，它的第 `i` 个元素 `prices[i]` 表示某支股票第 `i` 天的价格。

设计算法计算所能获取的**最大利润**：最多可以完成 **k 笔**交易（买入并卖出算一笔），同时最多只能持有一支股票（卖出后才能再次买入）。

数据范围：`1 <= k <= 100`，`1 <= prices.length <= 1000`，`0 <= prices[i] <= 1000`。

### 示例

```
输入：k = 2, prices = [2,4,1]
输出：2
解释：第 1 天（价格 2）买入、第 2 天（价格 4）卖出，利润 2；
     k 用不完没关系，一笔交易即是最优。

输入：k = 2, prices = [3,2,6,5,0,3]
输出：7
解释：第 2 天（价格 2）买入、第 3 天（价格 6）卖出，第一笔利润 4；
     第 5 天（价格 0）买入、第 6 天（价格 3）卖出，第二笔利润 3，总计 7。
```

## 解题思路

**二维状态机 DP**（O(n·k) 时间、O(n·k) 空间）——123 题「至多两笔」四变量滚动的推广。

### 先裁剪 k：交易次数有天然上限

一笔交易至少占两天（买入日 + 卖出日），`n` 天里最多容纳 `n//2` 笔不相交的交易，所以先令 `k = min(k, n // 2)`：

- 正确性不受影响——多出来的次数本来就用不掉；
- `k <= 100` 但 `n` 可到 1000，裁剪后 `n·k <= n²/4`，DP 规模始终安全；
- 当 `k >= n//2` 时问题退化为 122 题「不限次数」，本题的 DP 自动覆盖这一情形。

### 状态：持股 / 空仓 × 已完成交易层数

- `buy[i][j]`：第 `i` 天结束、**持股**、已完成第 `j+1` 次买入的最大收益；
- `sell[i][j]`：第 `i` 天结束、**空仓**、已完成第 `j+1` 次卖出的最大收益；
- `sell[i][0]` 恒为 0——从未买入过，"不交易"永远是一个合法状态。

第 `i` 天对每个状态取 `max(维持原状, 今天操作)`：

1. `buy[i][j] = max(buy[i-1][j], sell[i-1][j] - prices[i])`——今天完成第 `j+1` 次买入，从前一天**同层**空仓状态转入；
2. `sell[i][j] = max(sell[i-1][j], buy[i-1][j-1] + prices[i])`——今天完成第 `j+1` 次卖出，从前一天**低一层**持股状态转入。

注意两个转移都引用**前一天**的值，因此每笔交易天然跨越至少两天（昨天买、今天卖），这正是 `k <= n//2` 裁剪的依据。

初始：第 0 天只能完成第一次买入，`buy[0][0] = -prices[0]`、`sell[0][0] = 0`，`j >= 1` 的状态不可达，置为 `-inf` 哨兵——它让 `max` 永远选不中非法状态，省去一堆 if 判断。

答案：`max(sell[n-1])`——「至多 k 笔」允许少做或不做，取所有卖出层的最大值。

### 手算走一遍 `k = 2, prices = [3,2,6,5,0,3]` 的表

（`sell[i][0] ≡ 0` 未列出）

| i | price | buy[i][0] | buy[i][1] | buy[i][2] | sell[i][1] | sell[i][2] |
|---|-------|-----------|-----------|-----------|------------|------------|
| 0 | 3 | -3 | -∞ | -∞ | -∞ | -∞ |
| 1 | 2 | -2 | -∞ | -∞ | -1 | -∞ |
| 2 | 6 | -2 | -7 | -∞ | **4** | -∞ |
| 3 | 5 | -2 | -1 | -∞ | 4 | -2 |
| 4 | 0 | **0** | **4** | -2 | 4 | -1 |
| 5 | 3 | 0 | 4 | -2 | 4 | **7** |

最终 `sell[5][2] = 7`：正是「2 买 6 卖 + 0 买 3 卖」两笔交易。`buy[4][1] = 4` 承接 `sell[3][1] = 4`（第 5 天价格 0 时第二次买入），次日以 3 卖出得 7——层与层之间的衔接一目了然。

### 复杂度分析

- **时间复杂度**：O(n·k)，两层循环逐状态转移；
- **空间复杂度**：O(n·k)，`buy`/`sell` 两张表；由于只引用前一天，可滚动数组优化到 O(k)。

## 代码实现

```python
class Solution:
    def maxProfit(self, k: int, prices: list[int]) -> int:
        n = len(prices)
        # 一笔交易至少占两天（买入日 + 卖出日），有效交易数不超过 n//2
        k = min(k, n // 2)
        # buy[i][j]：第 i 天结束、已完成第 j+1 次买入（持股）的最大收益
        # sell[i][j]：第 i 天结束、已完成第 j+1 次卖出（空仓）的最大收益
        buy = [[0] * (k + 1) for _ in range(n)]
        sell = [[0] * (k + 1) for _ in range(n)]

        # 初始：第 0 天只能完成第一次买入，j >= 1 不可达
        buy[0][0] = -prices[0]
        sell[0][0] = 0
        for j in range(1, k + 1):
            buy[0][j] = sell[0][j] = float("-inf")

        for i in range(1, n):
            # 第 0 层：从未卖出过，只能继续持有或今天首次买入
            buy[i][0] = max(buy[i - 1][0], sell[i - 1][0] - prices[i])
            for j in range(1, k + 1):
                # 今天完成第 j+1 次买入：从前一天同层的空仓状态转入
                buy[i][j] = max(buy[i - 1][j], sell[i - 1][j] - prices[i])
                # 今天完成第 j+1 次卖出：从前一天低一层的持股状态转入
                sell[i][j] = max(sell[i - 1][j], buy[i - 1][j - 1] + prices[i])

        # 「至多 k 笔」允许少做或不做，取所有卖出层的最大值
        return max(sell[n - 1])
```

### 代码解析

- **`-inf` 哨兵**：`j >= 1` 的初始不可达状态全部置为负无穷，`max` 永远选不中它们，无需特判"前 `i` 天不够做 `j` 笔交易"；
- **为什么 `buy` 单独处理 `j = 0`**：第 0 层持股只能来自"更早买入后继续持有"或"今天首次买入"（`sell[i-1][0] - prices[i]` 即 `-prices[i]`），与高层转移结构相同，拆出来写只是避免越界；
- **为什么返回 `max(sell[n-1])`**：「至多 k 笔」的最优解可能只用 `j < k` 层，甚至一笔不做（全递减时答案为 0），所以对整行取最大而不是只取 `sell[n-1][k]`；
- **可退化性**：`k = 1` 时退化为 121 题，`k = 2` 时等价于 123 题（可用四个变量滚动优化到 O(1) 空间），`k >= n//2` 时等价于 122 题贪心。

## 测试用例

```python
def test_solution() -> None:
    solution = Solution()
    # 官方示例 1：单笔最优 4 - 2 = 2
    assert solution.maxProfit(2, [2, 4, 1]) == 2
    # 官方示例 2：两笔 (6-2) + (3-0) = 7
    assert solution.maxProfit(2, [3, 2, 6, 5, 0, 3]) == 7
    # 边界：单天无法交易（k 被裁剪为 0）
    assert solution.maxProfit(100, [5]) == 0
    # 两天单调：只能做一笔 3 - 1 = 2
    assert solution.maxProfit(2, [1, 3]) == 2
    # 单调递减：不交易即最优
    assert solution.maxProfit(2, [7, 6, 4, 3, 1]) == 0
    # k 超过 n//2 时等价于不限次数（122 题）：拼出所有上坡 5 - 1 = 4
    assert solution.maxProfit(10, [1, 2, 3, 4, 5]) == 4
    # 两笔优于一笔：(4-1) + (8-2) = 9 > 单笔最大 8 - 1 = 7
    assert solution.maxProfit(2, [1, 4, 2, 8]) == 9
    # 三笔优于一两笔：(4-1) + (8-2) + (9-3) = 15，限两笔时 (8-1) + (9-3) = 13
    assert solution.maxProfit(3, [1, 4, 2, 8, 3, 9]) == 15
    assert solution.maxProfit(2, [1, 4, 2, 8, 3, 9]) == 13
```

## 总结

1. 「至多 k 笔交易」的通解是给状态机加一维**交易层**：`buy[i][j]`/`sell[i][j]` 两张表，买入在同层转移、卖出跨层衔接，121/122/123 全是它的特例；
2. 两处关键技巧：`k = min(k, n//2)` 裁剪掉用不到的交易次数并控制 DP 规模；`-inf` 哨兵把"不可达状态"挡在 `max` 门外，代码无需任何特判；
3. 转移只引用前一天的值，空间可滚动优化到 O(k)；加上冷冻期/手续费（309/714）也只需在卖出转移上做减法，模式完全复用。
