> 周赛题的「操作包装」往往只是外壳：删前缀和后缀、剩下非空，本质就是枚举所有非空连续子数组。识破这层转化，题目立刻变成经典的「按结尾计数」DP。

## 题目

LeetCode 3524. Find X Value of Array I（求出数组的 X 值 I，第 446 场周赛）

Difficulty: **Medium**

给你一个由**正整数**组成的数组 `nums` 和一个正整数 `k`。

你可以执行**一次**操作：移除任意一对互不重叠的前缀和后缀（前缀、后缀都**可以为空**），但移除后 `nums` 必须仍然**非空**。

数组的 **x 值**定义为：操作后剩余元素的**乘积**除以 `k` 余数为 `x` 的操作数量。返回大小为 `k` 的数组 `result`，`result[x]` 即 x 值（`0 <= x < k`）。

### 示例

```
示例 1：
输入：nums = [1,2,3,4,5], k = 3
输出：[9,2,4]

示例 2：
输入：nums = [1,2,4,8,16,32], k = 4
输出：[18,1,2,0]

示例 3：
输入：nums = [1,1,2,1,1], k = 2
输出：[9,6]
```

## 解题思路

### 第一步：剥掉操作外壳（最关键）

「移除一个前缀 + 一个后缀，剩余非空」之后，剩下的恰好是一个**非空连续子数组** `[l, r]`；反过来，任意选定一个非空子数组 `[l, r]`，移除方式也被唯一确定（删掉 `l` 之前的前缀和 `r` 之后的后缀）。

这是一个一一对应，所以：

```
result[x] = 乘积 mod k 等于 x 的非空子数组个数
```

问题转化为经典的「按余数统计子数组」。

### 第二步：为什么不能用前缀积 + 除法？

子数组和可以用「前缀和之差」快速枚举，但乘积在模 `k` 下**没有等价手段**：想用前缀积相除，需要乘法逆元，而逆元只在余数与 `k` 互质时存在。本题 `k` 不保证是质数（例如 `k=4`），逆元不一定存在，此路不通。

### 第三步：按结尾位置做 DP

定义：

```
dp[r] = 以当前遍历位置结尾、乘积 mod k 等于 r 的子数组个数
```

处理新元素 `num`，令 `val = num % k`，以当前位置结尾的子数组只有两个来源：

1. **新开**：只包含 `num` 自己 → `next[val] += 1`；
2. **扩展**：接在以上一位置结尾的子数组后面。若原子数组余数为 `r`，新余数为 `(r * val) % k`：

```
next[(r * val) % k] += dp[r]
```

依据模运算性质 `(a*b) mod k = ((a mod k)*(b mod k)) mod k`，全程只维护余数即可，连 `num` 本身的大小（可达 10⁹）都不影响。

最后把每个位置的 `next` 按余数累加进答案——所有子数组按结尾位置不重不漏地归类一次，总和就是总计数。

### 两个实现细节

1. **计数要用 `long long`**：子数组总数为 `n(n+1)/2`，`n` 可达 10⁵ 时约 5×10⁹，超过 int 范围。
2. **余数乘法防御性提升**：`(1LL * val * r) % k`。虽然 `k <= 5` 时 int 也不会溢出，但这是处理模乘的标准写法，迁移到 k 较大的题目（如 3525 题的进阶版）也不会出错。

### 复杂度分析

- **时间复杂度**：O(n·k)，`k <= 5`，实际接近 O(n)。
- **空间复杂度**：O(k)，滚动数组，与 n 无关。

## 代码实现

{% raw %}
```cpp
class Solution {
public:
    vector<long long> resultArray(vector<int> &nums, int k) {
        // ret[r]：所有位置上，乘积模 k 余 r 的子数组个数之和
        vector<long long> ret(k, 0);

        // dp[r]：以上一位置结尾、乘积模 k 余 r 的子数组个数
        vector<long long> dp(k, 0);
        for (auto num : nums) {
            int val = num % k;
            vector<long long> next_dp(k, 0);
            // 以当前元素单独构成一个新子数组
            next_dp[val] += 1;

            // 把当前元素接到上一位置结尾的每个子数组后面
            for (int r = 0; r < k; r++) {
                if (dp[r] > 0) {
                    int next_val = (1LL * val * r) % k;
                    next_dp[next_val] += dp[r];
                }
            }

            // 以当前位置结尾的子数组计入总答案
            for (int r = 0; r < k; r++) {
                ret[r] += next_dp[r];
            }

            dp = std::move(next_dp);
        }

        return ret;
    }
};
```
{% endraw %}

### 代码解析

- `next_dp` 每轮新建为全 0，天然完成「滚动」：这一轮结束后它就是新一轮的 `dp`，用 `std::move` 转移避免拷贝整个 vector。
- `if (dp[r] > 0)` 是小优化：`k` 只有 5 时省不了多少，但在 k 较大的变体中可以跳过大量零状态。
- `dp` 只依赖上一位置，不保留历史行；历史信息已经通过累加进入 `ret`，这是把「二维表求和」压缩成「边算边累加」的常用手法。

## 总结

这道题有两道坎：第一道是**读题转化**，把「移除前缀后缀的操作数」翻译成「非空子数组数」，翻译不出来就会被题面绕晕；第二道是意识到乘积模运算**不能照搬前缀和的差分套路**（逆元不一定存在），从而转向「以结尾位置分类」的线性 DP。这个 DP 模板——`新开一个` + `从上个结尾转移` + `按位置累加答案`——是所有「统计满足某性质的子数组个数」问题的通用骨架，子数组和、子数组异或、子数组乘积都能套，值得练成肌肉记忆。
