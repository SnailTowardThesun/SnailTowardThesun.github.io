> 判定三点共线最稳的办法是叉积：向量 (dx1, dy1) 与 (dx2, dy2) 的叉积为 0 即共线，全程整数无精度问题。斜率哈希虽是主流解法，但以浮点数作键存在理论上的精度碰撞风险，约分成最简分数才算严谨。

## 题目

LeetCode 149. Max Points on a Line（直线上最多的点数）

Difficulty: **Hard**

给你一个数组 `points`，其中 `points[i] = [xi, yi]` 表示 **X-Y** 平面上的一个点。求最多有多少个点在同一条直线上。

注意：`points` 中的所有点**互不相同**。

### 示例

```
输入：points = [[1,1],[2,2],[3,3]]
输出：3

输入：points = [[1,1],[3,2],[5,3],[4,1],[2,3],[1,4]]
输出：4
解释：直线 x + y = 5 经过 (1,4)、(2,3)、(3,2)、(4,1) 四个点。
```

## 解题思路

### 锚点 + 斜率哈希

两点确定一条直线，而过同一个点的直线由**斜率**唯一区分。于是：

1. 依次把每个点 `i` 当作**锚点**，只看它之后的点 `j`（之前的点已在更早的锚点轮次里统计过）；
2. 计算 `i → j` 的斜率 `k = dy / dx`，用哈希表 `cnt` 统计每种斜率出现的次数——斜率相同的点必与锚点共线；垂直线 `dx = 0` 统一记为 `inf`；
3. 同一锚点下出现最多的斜率，就是「过 `i` 的最多点共线数」，加 1 补上锚点本身；对所有锚点取最大值。

因为题目保证所有点互不相同，不会出现「重合点」——重合点与锚点在**任何方向**上都共线，否则需要单独计数。

### 手算示例 2

以 `(1,4)` 为锚点：到 `(2,3)` 斜率 `-1`，到 `(3,2)` 斜率 `-1`，到 `(4,1)` 斜率 `-1`——`cnt[-1] = 3`，答案 `3 + 1 = 4`。

### 关于浮点斜率的精度

`dy / dx` 作为浮点数直接当哈希键，两条不同直线的斜率理论上可能被舍入到同一个 `float`，导致误判共线。更严谨的做法是用 `gcd` 把 `(dy, dx)` 约分成最简分数并统一符号（例如强制 `dx > 0`，`dx == 0` 时强制 `dy > 0`），用整数元组作键。本题坐标范围 `[-10^4, 10^4]`，浮点方案在实际测试中通过，但遇到更大的坐标范围建议换成分数键。

### 复杂度分析

| 项目 | 复杂度 |
|------|--------|
| 时间 | `O(n^2)`——每个锚点扫一遍其后的点 |
| 空间 | `O(n)`——每轮锚点的哈希表 |

## 代码实现

```python
from cmath import inf


class Solution:
    def maxPoints(self, points: list[list[int]]) -> int:
        ret = 0
        for i in range(len(points)):
            cnt = {}
            for j in range(i + 1, len(points)):
                dx, dy = points[j][0] - points[i][0], points[j][1] - points[i][1]
                if dx != 0:
                    k = dy / dx
                else:
                    k = inf

                if cnt.get(k) is None:
                    cnt[k] = 1
                else:
                    cnt[k] += 1

                ret = max(ret, cnt[k])

        return ret + 1
```

### 代码解析

- **只看后面的点**：`j` 从 `i + 1` 开始，每对点只在较小下标的锚点轮次中统计一次，避免重复又不漏；
- **垂直线的处理**：`dx == 0` 时所有点都归到键 `inf`，无论 `dy` 正负——它们本就在同一条竖线上；
- **返回 `ret + 1`**：`cnt` 统计的是「除锚点之外」的共线点数，单点输入时内层循环不执行、`ret = 0`，返回 1 正好符合题意。

## 测试用例

```python
def test_max_points():
    s = Solution()
    assert s.maxPoints([[1, 1], [2, 2], [3, 3]]) == 3
    assert s.maxPoints([[1, 1], [3, 2], [5, 3], [4, 1], [2, 3], [1, 4]]) == 4
    assert s.maxPoints([[0, 0]]) == 1  # 单点
```

另外用叉积判共线的 `O(n^3)` 暴力做了 300 组随机点集的对拍（坐标范围 `[-5, 5]`、最多 12 个点），结果全部一致。

## 总结

- 「过同一点的直线由斜率唯一区分」把几何问题化成了哈希计数，`O(n^2)` 枚举锚点即可；
- 互不相同的点是题目给的关键前提，去掉它就得单独处理重合点；
- 浮点斜率够用但不严谨，最简分数 `(dy/g, dx/g)` 加统一符号才是数学上无歧义的键。
