# 算法系列--拓扑排序：把依赖关系拉成一条直线

## 为什么需要拓扑排序

选课时经常遇到这样的约束：学「数据结构」之前要先学「程序设计」，学「算法」之前要先学「数据结构」和「离散数学」。把每门课看成一个点，每条「先学 A 再学 B」看成一条从 A 指向 B 的有向边，就得到一张有向图。我们想要的，是把所有课排成一个线性顺序，使得**每条边都从前面指向后面**——这就是拓扑排序（Topological Sort）。

同一个模型反复出现在工程里：

- **构建系统**：`make`、Gradle、Bazel 按目标之间的依赖决定编译顺序；
- **包管理器**：pip、npm、cargo 安装依赖时先装被依赖者；
- **任务调度**：工作流引擎（Airflow 的 DAG 就是字面意义上的「有向无环图」）决定任务执行次序；
- **电子表格**：单元格公式互相引用，重算时必须先算被引用的格子；
- **编译器**：模块初始化顺序、符号解析、指令调度。

这类问题有两个基本事实：

1. **有解当且仅当图中没有环**。如果 A 依赖 B、B 又依赖 A，谁也排不到前面。所以能做拓扑排序的图叫 DAG（Directed Acyclic Graph，有向无环图）；
2. **解通常不唯一**。两门互不依赖的课谁先谁后都行。算法只保证给出**一个**合法顺序，题目要求特定顺序时需要额外规则（比如字典序最小）。

拓扑排序算法因此同时回答两个问题：这张图有没有环？如果没有，给我一个合法顺序。LeetCode 207 问的是前者，210 问的是后者。

## 核心思想

先约定几个词：

- **入度**（in-degree）：指向该节点的边数，即「它还有多少个前置没完成」；
- **出度**（out-degree）：从该节点出发的边数；
- **源点**：入度为 0 的节点，没有任何前置，可以立刻执行。

全部推导建立在一条性质上：**DAG 中一定存在入度为 0 的节点**。反证：如果每个节点入度都至少为 1，从任意节点出发沿反向边一直往前走，永远走得下去；节点有限，走着走着必然回到某个已经经过的节点，这就构成了环，与「无环」矛盾。

有了这条性质，就有两条经典路线。

### 路线一：Kahn 算法——不断摘掉源点

思路直白：源点没有前置，先排它；排掉之后它指出去的边也随之消失，于是可能有新的节点变成源点；重复直到图空。

以 LeetCode 210 的示例 2 为例，4 门课，先修关系 `[[1,0],[2,0],[3,1],[3,2]]`，即边 `0→1、0→2、1→3、2→3`：

```text
    0
   / \
  v   v
  1   2
   \ /
    v
    3

入度：indegree = [0, 1, 1, 2]
```

按步骤摘：

| 步骤 | 队列（入度为 0） | 出队 | 入度变化 | 结果 |
|---|---|---|---|---|
| 初始 | `[0]` | — | `[0, 1, 1, 2]` | `[]` |
| 1 | `[1, 2]` | 0 | 1 和 2 降为 0 | `[0]` |
| 2 | `[2]` | 1 | 3 降为 1 | `[0, 1]` |
| 3 | `[3]` | 2 | 3 降为 0 | `[0, 1, 2]` |
| 4 | `[]` | 3 | — | `[0, 1, 2, 3]` |

四个节点全部出队，`[0, 1, 2, 3]` 就是一个拓扑序。

**为什么正确**：一个节点入度降到 0 的那一刻，意味着所有指向它的节点都已经出队、都已经排在结果里了，所以它排在它们后面是安全的。每条边都恰好让终点的入度减一次，没有多算也没有漏算。

**怎么判环**：如果图里有环，环上的每个节点都至少有一条来自环内的入边，这条边永远不会被摘掉——它们的入度永远到不了 0，永远进不了队列。于是算法结束时结果长度小于 `n`，剩下的正是环上以及环下游的节点。**判环只需比较结果长度与节点数。**

### 路线二：DFS 后序逆序——先把能到的都走完

另一种视角：对一个节点做 DFS，把它能到达的所有后继都处理完之后，再把它自己记下来。这个「记下来」的顺序叫**后序**；把后序整体反转，就是拓扑序。

为什么成立：考虑任意一条边 `u → v`。DFS 处理 `u` 时会去看 `v`：

- `v` 还没访问过：递归进去，`v` 会先于 `u` 完成；
- `v` 已经完成：它早就在后序里了，自然在 `u` 之前；
- `v` 正在访问中（还在递归栈上）：说明从 `v` 出发能走到 `u`，而 `u` 又有边指向 `v`——这是一条**回边**，图中有环。

所以只要无环，每条边的终点都比起点先完成，后序逆序中起点就在终点之前。

实现时给节点染三种颜色，是 DFS 判环的标准写法：

```text
白：还没访问
灰：正在访问——在当前递归栈上，它的后继还没全部处理完
黑：访问完成——所有后继都已完成

DFS 途中遇到灰色后继  =>  当前路径绕回了自己  =>  有环
```

同一个例子，从 0 出发（邻接表 `0: [1, 2]`，`1: [3]`，`2: [3]`）：

```text
dfs(0) 灰
  dfs(1) 灰
    dfs(3) 灰 -> 没有后继 -> 黑，后序 [3]
  1 黑，后序 [3, 1]
  dfs(2) 灰
    3 已是黑色，跳过
  2 黑，后序 [3, 1, 2]
0 黑，后序 [3, 1, 2, 0]

反转 => [0, 2, 1, 3]
```

这正好是 LeetCode 210 示例给出的答案 `[0,2,1,3]`——与 Kahn 得到的 `[0,1,2,3]` 不同，但同样合法。

## Python 实现

两个函数共用同一套约定：节点编号 `0 .. n-1`，`edges` 里的 `(u, v)` 表示 `u` 必须排在 `v` 之前（有向边 `u -> v`），有环时返回 `None`。

### Kahn 算法

```python
from collections import deque


def topological_sort(n: int, edges: list[tuple[int, int]]) -> list[int] | None:
    """Kahn 算法：返回 0..n-1 的一个拓扑序；图中有环时返回 None。

    edges 里的 (u, v) 表示 u 必须排在 v 之前，即有向边 u -> v。
    """
    adj: list[list[int]] = [[] for _ in range(n)]
    indegree = [0] * n
    for u, v in edges:
        adj[u].append(v)
        indegree[v] += 1

    queue = deque(i for i in range(n) if indegree[i] == 0)
    order: list[int] = []
    while queue:
        u = queue.popleft()
        order.append(u)
        for v in adj[u]:
            indegree[v] -= 1
            if indegree[v] == 0:
                queue.append(v)

    return order if len(order) == n else None
```

### DFS 三色标记

```python
def topological_sort_dfs(n: int, edges: list[tuple[int, int]]) -> list[int] | None:
    """DFS 三色标记 + 后序逆序：返回一个拓扑序；图中有环时返回 None。"""
    adj: list[list[int]] = [[] for _ in range(n)]
    for u, v in edges:
        adj[u].append(v)

    WHITE, GRAY, BLACK = 0, 1, 2
    color = [WHITE] * n
    postorder: list[int] = []

    def dfs(u: int) -> bool:
        color[u] = GRAY  # 进入递归栈
        for v in adj[u]:
            if color[v] == GRAY:  # 指回了栈上的节点：回边，有环
                return False
            if color[v] == WHITE and not dfs(v):
                return False
        color[u] = BLACK  # 所有后继都完成，u 才算完成
        postorder.append(u)
        return True

    for u in range(n):
        if color[u] == WHITE and not dfs(u):
            return None
    postorder.reverse()
    return postorder
```

## 关键实现解析

### 边的方向是第一大坑

LeetCode 207 / 210 给的 `prerequisites[i] = [a, b]` 含义是「先修 `b` 才能修 `a`」，对应的边是 `b -> a`，入度加在 `a` 上。写反成 `a -> b` 的后果很有迷惑性：

- 207 只需判环，而**一张图有环当且仅当它的反图有环**，所以方向反了照样能过；
- 210 要输出顺序，方向反了会得到一个完全倒置的序列，直接判错。

**207 通过不能作为 210 建图方向正确的证据。** 建图那两行写完，先用示例手算一遍入度数组，再往下写。

### 孤立节点必须出现在结果里

没有任何边连着的节点入度为 0，会在第一轮就进入队列，自然被输出。但前提是邻接表和入度数组按 `n` 建，而不是只为边里出现过的节点建。只扫 `edges` 建 dict 的写法会把孤立节点漏掉，`len(order) == n` 的判环条件也随之失效。

### 两种判环的语义不同

- Kahn 是**事后**判断：跑完看结果长度是否等于 `n`，不等于就有环，`order` 里留下的是「环上游能排出来的部分」；
- DFS 是**途中**判断：碰到灰色后继立刻返回 `False`。要注意只有**灰色**才算环，黑色后继是已经处理完的另一条路径汇合过来，完全正常——把 `color[v] != WHITE` 一律当成环，会把示例里 `2 -> 3`（3 已黑）误判。

### 队列要用 `deque`

Kahn 的队列如果用 `list` 配 `pop(0)`，每次出队是 `O(n)` 的整体搬移，`n` 大时把整个算法拖成 `O(n²)`。`collections.deque` 的 `popleft` 是 `O(1)`。

### DFS 版本的递归深度

一条 2000 个节点的长链会让 `dfs` 递归 2000 层，超过 Python 默认的 1000 层上限，抛 `RecursionError`。LeetCode 线上环境把上限调得很高所以能过，本地跑测试则会炸。两条出路：`sys.setrecursionlimit` 临时抬高，或者干脆用天然迭代的 Kahn。这也是实践中 Kahn 更常被首选的原因之一。

### 重复边与自环

Kahn 对重复边天然正确：同一条边出现两次，入度加两次、出队时也减两次，只要 `adj` 和 `indegree` 用同一份 `edges` 构建就不会出错。自环 `u -> u` 会让 `u` 的入度永远不为 0，被正确识别为环；DFS 版本里 `u` 自己是灰色，看到后继 `u` 同样立刻判环。

## 使用示例

```python
edges = [(0, 1), (0, 2), (1, 3), (2, 3)]

print(topological_sort(4, edges))  # [0, 1, 2, 3]
print(topological_sort_dfs(4, edges))  # [0, 2, 1, 3]

# 补一条 3 -> 0 形成环，两种实现都返回 None
print(topological_sort(4, edges + [(3, 0)]))  # None
print(topological_sort_dfs(4, edges + [(3, 0)]))  # None
```

两种实现在同一张图上给出了不同但都合法的顺序，印证了「解不唯一」。

LeetCode 207 和 210 就是这个函数的两种用法——前者只看有没有解，后者把解原样交出去，有环时按题意返回空列表。注意 `[a, b]` 到 `(b, a)` 的方向翻转：

```python
def can_finish(num_courses: int, prerequisites: list[list[int]]) -> bool:
    # prerequisites[i] = [a, b] 表示先修 b 再修 a：边 b -> a
    return topological_sort(num_courses, [(b, a) for a, b in prerequisites]) is not None


def find_order(num_courses: int, prerequisites: list[list[int]]) -> list[int]:
    order = topological_sort(num_courses, [(b, a) for a, b in prerequisites])
    return order if order is not None else []
```

## 测试设计

拓扑序不唯一，所以**不能拿固定列表比对**，只能校验性质：结果是 `0..n-1` 的一个排列，且每条边都从前指向后。只有顺序唯一的图（如线性链）才能直接 `==`。

```python
def is_topological_order(order: list[int], n: int, edges: list[tuple[int, int]]) -> bool:
    """答案不唯一时只能校验性质：是 0..n-1 的排列，且每条边都从前指向后。"""
    if sorted(order) != list(range(n)):
        return False
    pos = {node: i for i, node in enumerate(order)}
    return all(pos[u] < pos[v] for u, v in edges)


def test_topological_sort() -> None:
    for topo in (topological_sort, topological_sort_dfs):
        # 官方示例：答案不唯一，只校验合法性
        edges = [(0, 1), (0, 2), (1, 3), (2, 3)]
        assert is_topological_order(topo(4, edges), 4, edges)

        # 线性链：顺序唯一，可以直接比对
        assert topo(4, [(0, 1), (1, 2), (2, 3)]) == [0, 1, 2, 3]

        # 没有任何边：任意排列都合法，但必须包含所有节点
        assert sorted(topo(5, [])) == [0, 1, 2, 3, 4]

        # 孤立节点 + 一条边：孤立的 0 和 3 也必须出现在结果里
        edges = [(1, 2)]
        assert is_topological_order(topo(4, edges), 4, edges)

        # 环：整体无解
        assert topo(3, [(0, 1), (1, 2), (2, 0)]) is None

        # 环藏在一个分量里，另一个分量无环，整体仍然无解
        assert topo(5, [(0, 1), (2, 3), (3, 2)]) is None

        # 自环
        assert topo(2, [(0, 1), (1, 1)]) is None
```

这组断言重点钉住：孤立节点不丢（按 `n` 建表）、环的判定不受无环分量干扰、自环被识别，以及两种实现在所有场景下结论一致。

## 变体与延伸

拓扑排序本身很短，真正的变化在它周围：

- **字典序最小的拓扑序**：把 Kahn 的 `deque` 换成最小堆（`heapq`），每次弹出编号最小的源点。DFS 路线不容易做到这一点，是 Kahn 的一项优势；
- **判断拓扑序是否唯一**：Kahn 过程中若某一步队列里同时有两个以上节点，它们可以互换，顺序就不唯一；全程队列长度恒为 1 则唯一；
- **沿拓扑序做 DP**：拓扑序保证处理一个节点时它的所有前驱都已处理完，于是「DAG 上的最长路径」「到每个节点的路径数」「可达集合」都能在一遍遍历里递推完成——LeetCode 2050（并行课程 III）求的就是带权最长路，1462（课程表 IV）求的是可达性传递闭包；
- **有环时的部分结果**：Kahn 结束时 `order` 里是环上游的全部节点，这正是 2115（从给定原材料中找到所有可以做出的菜）需要的答案；
- **反图上的拓扑**：802（找到最终的安全状态）把所有边反向，从出度为 0 的终点开始摘，摘得掉的就是安全节点；
- **无向图上的「剥叶子」**：310（最小高度树）从度为 1 的叶子一层层往里摘，最后剩下的一两个节点就是树心——不是严格的拓扑排序，但骨架完全是 Kahn。

## 复杂度与适用边界

设节点数 `V`、边数 `E`：

- 两种实现时间复杂度都是 `O(V + E)`：每个节点进出队列（或递归栈）一次，每条边被扫描一次；
- 空间 `O(V + E)`：邻接表 `O(V + E)`，入度数组、颜色数组、结果各 `O(V)`。

两条路线的取舍：

| | Kahn | DFS 后序逆序 |
|---|---|---|
| 实现方式 | 迭代 | 递归（深图有栈溢出风险） |
| 判环 | 事后看 `len(order)` | 途中碰灰色即返回 |
| 字典序最小 | 换最小堆即可 | 不方便 |
| 判唯一性 | 看队列长度 | 不方便 |
| 有环时 | 还能拿到环上游的部分结果 | 直接失败 |
| 顺带产物 | 入度数组 | 完成时间，可衔接强连通分量等算法 |

适用边界也要清楚：拓扑排序只对**有向图**有意义，无向图没有「谁先谁后」；有环就无解，若需求是「尽量多排」，Kahn 的部分结果就是最大可排集合；节点若是字符串或对象，在外层维护 `label -> index` 映射后再交给这两个连续整数版本处理，和并查集那篇的做法一致。

## 总结

- 拓扑排序回答两个问题：有向图有没有环；没有环时给出一个所有边都从前指向后的线性顺序。有解当且仅当是 DAG，解通常不唯一；
- Kahn 算法「不断摘源点」，迭代、好扩展（字典序、唯一性、部分结果），是首选；DFS 后序逆序靠三色标记判环，代码同样短，但要留心递归深度；
- 实践中的坑集中在建图：边的方向（207 过了不代表 210 方向对）、孤立节点（按 `n` 建表）、队列用 `deque`。算法本身只有十几行，图建对了就成功了一大半。
