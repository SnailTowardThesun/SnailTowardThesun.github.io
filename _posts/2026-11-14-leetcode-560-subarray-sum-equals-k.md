> 含负数时，窗口和不再随扩张或收缩单调变化，常规的按和值收缩策略不适用。前缀和配合哈希计数，可以直接统计与当前前缀和相差 k 的历史前缀。

## 题目

LeetCode 560. Subarray Sum Equals K（和为 K 的子数组）— HOT 100 子串/子数组

Difficulty: **Medium**

给你一个整数数组 `nums` 和一个整数 `k`，请你统计并返回该数组中**和为 `k` 的连续非空子数组的个数**。

约束：

- `1 <= nums.length <= 2 * 10^4`
- `-1000 <= nums[i] <= 1000`
- `-10^7 <= k <= 10^7`

### 示例

```text
输入：nums = [1,1,1], k = 2
输出：2

输入：nums = [1,2,3], k = 3
输出：2
```

## 解题思路

### 前缀和把「区间和」变成「两数之差」

子数组 `nums[i..j-1]` 的和 = 前缀和之差 `s[j] - s[i]`（约定 `s[0] = 0`，前缀和数组长度 n+1）。「和为 k」等价于：

```text
s[j] - s[i] = k   即   s[i] = s[j] - k
```

于是问题变成：对每个右端 `j`，数一数它左边有多少个前缀和等于 `s[j] - k`。这正是哈希表的活——`cnt[v]` 记录前缀和 `v` 已出现的次数。

### 先查后加：k = 0 的自配陷阱

扫描顺序是**先查后加**：先用 `cnt = {0: 1}` 记录空前缀，随后每读入一个数更新 `prefix`，累加 `cnt.get(prefix - k, 0)`，再记录当前前缀。这保证只匹配之前的前缀，即 `i < j`；当 `k = 0` 时也不会把当前前缀与自己配对。

### 手算示例（nums = [1,1,1], k = 2）

前缀和数组 `s = [0,1,2,3]`：

| j | s[j] | 查 cnt[s[j]-2] | 命中 | 计数后 cnt |
|---|------|---------------|------|-----------|
| 0 | 0 | 初始化空前缀，不查询 | — | {0:1} |
| 1 | 1 | cnt[-1] | 0 | {0:1, 1:1} |
| 2 | 2 | cnt[0] | 1 ← | {0:1, 1:1, 2:1} |
| 3 | 3 | cnt[1] | 1 ← | {0:1, 1:1, 2:1, 3:1} |

答案 2（子数组 `[1,1]` 两段）。

### 为什么不能按和值收缩窗口

`nums` 含负数：窗口右扩一格，和可能变小、也可能变大，没有单调性——「和超标就收缩」的逻辑失效。前缀和 + 哈希不依赖单调性，负数照常工作。例如 `[2,-1]`、`k=1` 时，若看到 2 就立即缩窗，会漏掉整个数组。

这不表示所有滑动窗口或计数问题都不能处理负数。No.3364 的定长窗口只是通过加减元素维护区间和，并未依据和值决定边界，所以允许负数；本题也可以 O(n²) 枚举计数，前缀和 + 哈希的优势是把平均时间降到 O(n)。

### 复杂度分析

- 时间复杂度：平均 `O(n)`——一次扫描，哈希查询与更新平均 O(1)；
- 辅助空间复杂度：`O(n)`——哈希表保存实际出现的前缀和；`prefix` 滚动维护，不再单独保存前缀和数组。

## 代码实现

```python
class Solution:
    def subarraySum(self, nums: list[int], k: int) -> int:
        ret = 0
        prefix = 0
        cnt = {0: 1}  # 空前缀，让从下标 0 开始的子数组也能被计数
        for x in nums:
            prefix += x
            # 先查询历史前缀，再记录当前前缀，保证子数组非空
            ret += cnt.get(prefix - k, 0)
            cnt[prefix] = cnt.get(prefix, 0) + 1
        return ret
```

### 代码解析

- `prefix` 表示当前前缀的和值；它不是下标，变量命名与公式中的 `s[j]` 对应；
- `cnt.get(prefix - k, 0)` 在查询未出现的和值时返回 0，不会创建计数为 0 的无效条目；
- `cnt = {0: 1}` 代表空前缀，使从下标 0 开始的子数组也能被计数；
- 必须记录出现次数而非仅记录是否出现：相同前缀和可能对应多个合法起点。

## 测试用例

```python
def test_solution() -> None:
    solution = Solution()

    # ---- 官方示例 ----
    assert solution.subarraySum([1, 1, 1], 2) == 2
    assert solution.subarraySum([1, 2, 3], 3) == 2

    # ---- k = 0 陷阱：先查后加不自配；全零数组的每一段都算 ----
    assert solution.subarraySum([-1, -1, 1], 0) == 1
    assert solution.subarraySum([0, 0, 0], 0) == 6

    # ---- 负数数组：不能按和值收缩窗口，前缀和可解 ----
    assert solution.subarraySum([1, -1, 1, -1], 0) == 4

    # ---- 整个数组恰为一段 ----
    assert solution.subarraySum([3], 3) == 1

    # ---- 无解 ----
    assert solution.subarraySum([1, 2, 3], 7) == 0

    # ---- 负目标值与重复前缀：不能只记录某个前缀是否出现 ----
    assert solution.subarraySum([-1, -1, 1], -1) == 3
    assert solution.subarraySum([0], 0) == 1
    assert solution.subarraySum([1], 0) == 0

    # ---- 最大规模全零：每个非空子数组都有效 ----
    assert solution.subarraySum([0] * 20000, 0) == 20000 * 20001 // 2
```

提交前用「枚举所有起点累加」的 O(n²) 朴素版随机对照 2000 组（含负数与 k=0），与前缀和哈希版结果全部一致；手写期望值另用暴力单测复核。

## 总结

- 前缀和把区间和转成两数之差，哈希计数把「找起点」降为 O(1) 查表，整体 O(n)；
- 先查后加保证 `i < j`，是 k = 0 不自配的全部细节；
- 含负数时不能依赖「和超标就收缩」；应根据具体窗口不变量选择算法。
