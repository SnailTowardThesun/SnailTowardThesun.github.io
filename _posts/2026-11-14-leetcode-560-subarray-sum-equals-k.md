> 数组带负数时滑窗就失效了——窗口和不再单调。前缀和 + 哈希计数换了个角度：不找窗口，而是数「有多少个起点的前缀和恰好差 k」。

## 题目

LeetCode 560. Subarray Sum Equals K（和为 K 的子数组）— HOT 100 子串/子数组

Difficulty: **Medium**

给你一个整数数组 `nums` 和一个整数 `k`，请你统计并返回该数组中**和为 `k` 的连续子数组的个数**。

约束：

- `1 <= nums.length <= 2 * 10^4`
- `-1000 <= nums[i] <= 1000`
- `-10^7 <= k <= 10^7`

### 示例

```text
输入：nums = [1,1,1], k = 2
输出：2

输入：nums = [1,2,3], k = 3
输出：2
```

## 解题思路

### 前缀和把「区间和」变成「两数之差」

子数组 `nums[i..j-1]` 的和 = 前缀和之差 `s[j] - s[i]`（约定 `s[0] = 0`，前缀和数组长度 n+1）。「和为 k」等价于：

```text
s[j] - s[i] = k   即   s[i] = s[j] - k
```

于是问题变成：对每个右端 `j`，数一数它左边有多少个前缀和等于 `s[j] - k`。这正是哈希表的活——`cnt[v]` 记录前缀和 `v` 已出现的次数。

### 先查后加：k = 0 的自配陷阱

扫描顺序是**先查后加**：处理 `s[j]` 时先累加 `cnt[s[j] - k]`，再把 `s[j]` 计入哈希。这保证配对的 `i < j`；特别当 `k = 0` 时查询值恰等于自身，先查后加不会把自己配给自己。

### 手算示例（nums = [1,1,1], k = 2）

前缀和数组 `s = [0,1,2,3]`：

| j | s[j] | 查 cnt[s[j]-2] | 命中 | 计数后 cnt |
|---|------|---------------|------|-----------|
| 0 | 0 | cnt[-2] | 0 | {0:1} |
| 1 | 1 | cnt[-1] | 0 | {0:1, 1:1} |
| 2 | 2 | cnt[0] | 1 ← | {0:1, 1:1, 2:1} |
| 3 | 3 | cnt[1] | 1 ← | {0:1, 1:1, 2:1, 3:1} |

答案 2（子数组 `[1,1]` 两段）。

### 为什么不能滑动窗口

`nums` 含负数：窗口右扩一格，和可能变小、也可能变大，没有单调性——「和超标就收缩」的逻辑失效。前缀和 + 哈希不依赖单调性，负数照常工作；这也是它与「最小正和子数组」（No.3364）一类的本质区别：那题只求和的正负不依赖窗口单调收缩的合法性，而计数问题必须回到前缀和。

### 复杂度分析

- 时间复杂度：`O(n)`——预处理前缀和一趟、计数扫描一趟；
- 空间复杂度：`O(n)`——前缀和数组与哈希表（边扫边算可省去前缀和数组，只留哈希）。

## 代码实现

```python
from collections import defaultdict


class Solution:
    def subarraySum(self, nums: list[int], k: int) -> int:
        # 前缀和 s[j] = nums[0..j-1] 之和，s[0] = 0
        s = [0] * (len(nums) + 1)
        for i, x in enumerate(nums):
            s[i + 1] = s[i] + x

        ret = 0
        cnt: defaultdict[int, int] = defaultdict(int)  # 前缀和 -> 出现次数
        for j in s:
            # 先查后加：顺序保证 i < j，k=0 时不自配
            ret += cnt[j - k]
            cnt[j] += 1
        return ret
```

### 代码解析

- 两趟分离（先建前缀和数组、再扫计数）比边扫边算多一个数组，但「区间和 = 前缀差」的对应关系一眼可见；
- `cnt[j - k]` 用 `defaultdict(int)` 直接取值，不存在的键返回 0（顺带在表中留下条目，n ≤ 2×10⁴ 无碍）；
- 前缀和含 `s[0] = 0`，它让「从下标 0 开始的子数组」也能被 `s[j] - 0` 命中——漏掉 s[0] 是常见错误。

## 测试用例

```python
def test_solution() -> None:
    solution = Solution()

    # ---- 官方示例 ----
    assert solution.subarraySum([1, 1, 1], 2) == 2
    assert solution.subarraySum([1, 2, 3], 3) == 2

    # ---- k = 0 陷阱：先查后加不自配；全零数组的每一段都算 ----
    assert solution.subarraySum([-1, -1, 1], 0) == 1
    assert solution.subarraySum([0, 0, 0], 0) == 6

    # ---- 负数数组：滑窗失效、前缀和可解的场景 ----
    assert solution.subarraySum([1, -1, 1, -1], 0) == 4

    # ---- 整个数组恰为一段 ----
    assert solution.subarraySum([3], 3) == 1

    # ---- 无解 ----
    assert solution.subarraySum([1, 2, 3], 7) == 0
```

提交前用「枚举所有起点累加」的 O(n²) 朴素版随机对照 2000 组（含负数与 k=0），与前缀和哈希版结果全部一致；手写期望值另用暴力单测复核。

## 总结

- 前缀和把区间和转成两数之差，哈希计数把「找起点」降为 O(1) 查表，整体 O(n)；
- 先查后加保证 `i < j`，是 k = 0 不自配的全部细节；
- 含负数 ⟹ 窗口和无单调性 ⟹ 滑窗失效——识别「能不能滑窗」比会写滑窗更重要。
