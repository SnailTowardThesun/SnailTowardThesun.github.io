> 「字符值 × 位置」的加权求和是字符串统计的常见模型，Excel 列号、子串贡献计数、词频 TF-IDF 都是它的变体。

## 题目

LeetCode 3498. Reverse Degree of a String（字符串的反转度）

Difficulty: **Easy**

给定一个只包含小写英文字母的字符串 `s`，定义字符 `ch` 的**反转字母值**为：

```
reverseValue(ch) = 'z' - ch + 1，即 a=26, b=25, ..., z=1
```

也就是普通字母值（a=1..z=26）关于 27 的镜像。

字符串 `s` 的**反转度**定义为：对每个 **1 起始**下标 `i`，把 `s[i]` 的反转字母值乘以其下标 `i` 后求和。返回字符串 `s` 的反转度。

### 示例

```
示例 1：
输入：s = "abc"
输出：148
解释：a(26)*1 + b(25)*2 + c(24)*3 = 26 + 50 + 72 = 148。

示例 2：
输入：s = "zaza"
输出：160
解释：z(1)*1 + a(26)*2 + z(1)*3 + a(26)*4 = 1 + 52 + 3 + 104 = 160。
```

## 解题思路

### 直接模拟

题目本身就是一个加权求和公式，一次遍历即可：

- 第 `i`（0 起始）个字符的反转字母值：`26 - (ch - 'a')`；
- 它的位置乘数是 1 起始下标 `i + 1`；
- 两项相乘后累加。

### 两个易错点

1. **反转值公式是 `26 - (ch - 'a')`，不是 `27 - (ch - 'a')`**。代入边界验证：`a` 应为 26，用 26 式得到 26 ✓；若误用 27 式，`a` 会变成 27、`z` 变成 2，全部错位。
2. **下标是 1 起始**。循环用 0 起始下标时乘数要写 `i + 1`，漏掉 `+1` 会让所有项错位（首项乘 0 直接丢失）。

### 复杂度分析

- **时间复杂度**：O(n)，n 为字符串长度。
- **空间复杂度**：O(1)，只使用常数额外空间。

## 代码实现

{% raw %}
```cpp
class Solution {
public:
    int reverseDegree(string s) {
        int ret = 0;
        for (int i = 0; i < s.length(); i++) {
            // 反转字母值：a=26..z=1；位置乘数为 1 起始下标 i+1
            ret += (26 - (s.at(i) - 'a')) * (i + 1);
        }

        return ret;
    }
};
```
{% endraw %}

### 代码解析

- `s.at(i) - 'a'` 把字符映射成 0~25 的普通序号，再用 `26 -` 翻转成「a=26, z=1」。
- 全程整数运算，无开方、无浮点，结果量级上界约为 `26 * n*(n+1)/2`，本题约束下 int 足够。
- 也可以用范围 for 配合维护位置计数器，写成无下标的形式，但显式下标更贴近题意、不易弄错 1 起始乘数。

## 测试用例

{% raw %}
```cpp
TEST(Daily, 3498) {
    string s = "abc";
    auto ret = Solution().reverseDegree(s);
    EXPECT_EQ(ret, 148);

    // 交替字符：z(1)*1 + a(26)*2 + z(1)*3 + a(26)*4 = 160
    EXPECT_EQ(Solution().reverseDegree("zaza"), 160);

    // 边界用例：单个字符 z，反转值为 1，乘位置 1
    EXPECT_EQ(Solution().reverseDegree("z"), 1);

    // 边界用例：单个字符 a，反转值为 26，乘位置 1
    EXPECT_EQ(Solution().reverseDegree("a"), 26);
}
```
{% endraw %}

## 总结

作为周赛第一题，本题没有算法门槛，考察的是**题意转译的细心程度**：把「反转字母值」和「1 起始下标」两个定义准确落成代码。这类纯模拟题的通用防错法是「用边界样例反推公式」——先手算 `a` 和 `z` 的期望贡献（26 和 1），再核对代码表达式；再用最短非平凡样例（如单字符）验证位置乘数，确认无误后再提交。加权求和的思维框架还会在 Excel 列号、子串贡献计数等题中反复出现。
