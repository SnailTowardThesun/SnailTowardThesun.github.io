> 「每个窗口的最大值」不必每个窗口重扫一遍：堆版用懒删除——过期元素只在挡路时弹出；单调队列版更狠——比新元素小的直接淘汰，它们永远当不了最大值。

## 题目

LeetCode 239. Sliding Window Maximum（滑动窗口最大值）— HOT 100 子串/子数组

Difficulty: **Hard**

给你一个整数数组 `nums`，有一个大小为 `k` 的滑动窗口从数组的最左侧移动到数组的最右侧。你只能看到滑动窗口内的 `k` 个数字，窗口每次向右移动一位。返回**每个窗口位置的最大值**组成的数组。

约束：

- `1 <= nums.length <= 10^5`
- `-10^4 <= nums[i] <= 10^4`
- `1 <= k <= nums.length`

### 示例

```text
输入：nums = [1,3,-1,-3,5,3,6,7], k = 3
输出：[3,3,5,5,6,7]
解释：
窗口位置                  最大值
---------------          -----
[1  3  -1] -3  5  3  6  7   3
 1 [3  -1  -3] 5  3  6  7   3
 1  3 [-1  -3  5] 3  6  7   5
 1  3  -1 [-3  5  3] 6  7   5
 1  3  -1  -3 [5  3  6] 7   6
 1  3  -1  -3  5 [3  6  7]  7

输入：nums = [1], k = 1
输出：[1]
```

## 解题思路

### 堆 + 懒删除

窗口右滑到 `i` 时需要「窗口内（下标 > i-k）的最大值」：

1. 堆存 `(-值, 下标)`——Python `heapq` 是小根堆，取负把最大值顶到堆顶；下标用于判断元素是否已离开窗口；
2. 每步先把 `(-nums[i], i)` 压入堆，再检查堆顶：下标 `<= i-k` 说明已过期，弹出——**直到堆顶未过期为止**，堆顶取负即该窗口最大值；
3. 关键是「懒删除」：离开窗口的元素**不必**在它离开时立刻从堆里删掉（heapq 也做不到高效删除中间元素），只要它不挡在堆顶就不影响答案，挡路时再弹。

为什么正确：堆顶若是过期元素，它对应的下标已出窗口，它不可能是答案；弹出后新的堆顶要么未过期（它就是窗口内最大——窗口内所有元素都在堆里），要么继续过期继续弹。

### 进阶：单调递减双端队列 O(n)

维护一个下标队列，对应的值严格递减：新元素入队前，把队尾所有**小于它**的下标弹出（那些元素比新元素先过期又比它小，永远当不了最大值）；队首下标过期则出队。每个元素至多入队出队各一次，总 O(n)——比堆的 O(n log n) 更优，是这题的标准最优解。

### 复杂度分析

- **堆 + 懒删除**：时间 `O(n log n)`（每个元素至多进出堆各一次），空间 `O(n)`（堆中滞留的过期元素）；
- **单调队列**：时间 `O(n)`，空间 `O(k)`。

## 代码实现

```python
import heapq


class Solution:
    def maxSlidingWindow(self, nums: list[int], k: int) -> list[int]:
        n = len(nums)

        ans: list[int] = []
        # 堆存 (-值, 下标)：小根堆取负模拟大根堆，下标用于判窗口过期
        q = [(-nums[i], i) for i in range(k)]
        heapq.heapify(q)

        ans.append(-q[0][0])
        for i in range(k, n):
            heapq.heappush(q, (-nums[i], i))
            while q[0][1] <= i - k:  # 懒删除：堆顶过期才弹，弹到未过期为止
                heapq.heappop(q)
            ans.append(-q[0][0])

        return ans
```

### 代码解析

- **先压后清**：先把新元素压入再清理堆顶——新元素自己永不过期（它的下标就是当前最大的 `i`），顺序不会误删；
- 清理条件是 `q[0][1] <= i - k`（窗口左界外），过期元素可能堆积多个，用 `while` 弹到未过期为止；
- 初始窗口单独 `heapify` 建堆后取一次堆顶，循环从 `i = k` 开始滑——与 438 题的「首窗口单独判定」同一个节奏；
- `(-值, 下标)` 的元组序：先比值再比下标，值相同时堆顶取更大下标（更新鲜的），对正确性无碍。

## 测试用例

```python
def test_solution() -> None:
    solution = Solution()

    # ---- 官方示例 ----
    assert solution.maxSlidingWindow([1, 3, -1, -3, 5, 3, 6, 7], 3) == [3, 3, 5, 5, 6, 7]
    assert solution.maxSlidingWindow([1], 1) == [1]

    # ---- k = 1：窗口就是每个元素自身 ----
    assert solution.maxSlidingWindow([4, -2, 7], 1) == [4, -2, 7]

    # ---- k = n：整个数组只有一个窗口 ----
    assert solution.maxSlidingWindow([2, 9, 1, 5], 4) == [9]

    # ---- 单调递减：过期最大值逐个让位 ----
    assert solution.maxSlidingWindow([5, 4, 3, 2, 1], 2) == [5, 4, 3, 2]

    # ---- 单调递增：新元素总是新窗口最大值 ----
    assert solution.maxSlidingWindow([1, 2, 3, 4], 2) == [2, 3, 4]

    # ---- 相同元素：4 个元素 k=2 有 3 个窗口，并列最大值正确过期 ----
    assert solution.maxSlidingWindow([3, 3, 3, 3], 2) == [3, 3, 3]
```

提交前用「每个窗口重新取 max」的朴素版随机对照 1500 组，与堆版结果全部一致；手写期望值另用朴素版逐个复核（相同元素用例的窗口数 n-k+1 又是易错点，手写曾误为 2，机器复核为 3）。

## 总结

- 堆 + 懒删除：元素离开窗口时不管，堆顶过期才弹——把「删除」摊派给「挡路」时刻，O(n log n)；
- 单调队列是本题的标准最优解 O(n)：比新元素小的队尾直接淘汰，「永远当不了最大值的元素」根本不进队；
- 首窗口单独处理、循环从 `i = k` 滑起，与 438 的节奏一致——定长滑窗的通用骨架。
