> 「把零挪到末尾」的最优姿势不是挪零，而是挪非零：快指针挑出非零元素、慢指针标记落位，一次交换 O(n) 完成，非零相对顺序天然保持。

## 题目

LeetCode 283. Move Zeroes（移动零）— HOT 100 双指针

Difficulty: **Easy**

给定一个数组 `nums`，编写一个函数将所有 `0` 移动到数组的末尾，**同时保持非零元素的相对顺序**。必须**在不复制数组的情况下原地对数组进行操作**，并尽量减少操作次数。

约束：

- `1 <= nums.length <= 10^4`
- `-2^31 <= nums[i] <= 2^31 - 1`

### 示例

```text
输入：nums = [0,1,0,3,12]
输出：[1,3,12,0,0]

输入：nums = [0]
输出：[0]
```

## 解题思路

### 快慢双指针：挪非零而不是挪零

- `slow` 指向「下一个非零元素应落位」的位置——由于非零元素都已被搬到前面，`slow` 同时也是**当前最靠左的零**的位置；
- `fast` 向右扫描，每遇到一个非零元素，就与 `nums[slow]` 交换，然后 `slow` 前进一格；
- 循环不变量：任意时刻 `nums[0..slow)` 全是非零且保持原相对顺序，`nums[slow..fast)` 全是零。交换恰好把「一个零」换到后面、「一个非零」换到前面，两边的相对顺序都不被破坏；
- 前缀没有零时 `slow == fast`，交换是自己和自己，无害，无需特判。

### 反面教材：pop + append 为什么不行

直觉写法「遇到零就 `pop` 出来 `append` 到末尾」有两个坑：

1. **漏元素**：`nums.pop(left)` 后，原 `left+1` 的元素滑到 `left`，若紧接着 `left += 1` 就把它跳过了——相邻两个零必然翻车：`[0,0,1]` 会输出 `[0,1,0]`（期望 `[1,0,0]`）；
2. **复杂度**：`pop` 中间位置要把后半段整体前移，单个零 O(n)，最坏 `O(n²)`。

（若坚持这个思路，修法是移动零后**不推进** left——但复杂度仍是 O(n²)，不如交换法。）

### 手算示例 1（nums = [0,1,0,3,12]）

| fast | nums[fast] | 动作 | 数组状态 | slow |
|------|-----------|------|----------|------|
| 0 | 0 | 跳过 | [0,1,0,3,12] | 0 |
| 1 | 1 | 换 0/1 位 | [1,0,0,3,12] | 1 |
| 2 | 0 | 跳过 | [1,0,0,3,12] | 1 |
| 3 | 3 | 换 1/3 位 | [1,3,0,0,12] | 2 |
| 4 | 12 | 换 2/4 位 | [1,3,12,0,0] | 3 |

### 复杂度分析

- 时间复杂度：`O(n)`——一次遍历，每个元素至多参与一次交换；
- 空间复杂度：`O(1)`——原地操作，两个下标。

## 代码实现

```python
class Solution:
    def moveZeroes(self, nums: list[int]) -> None:
        """
        Do not return anything, modify nums in-place instead.
        """
        slow = 0  # 下一个非零元素的落位；也即当前最靠左的零
        for fast in range(len(nums)):
            if nums[fast] != 0:
                nums[slow], nums[fast] = nums[fast], nums[slow]
                slow += 1
```

### 代码解析

- 全部逻辑只有一个 if：非零就换到前面、零被动换到后面，「移动零」被反转成「收集非零」；
- 交换写法保证非零元素间的相对顺序（每次都是与「最靠前的零」交换，非零只会向前跳到连续非零区的末尾）；
- 「先覆写后补零」（快指针把非零抄到 slow 位置、最后把尾部填 0）少一半交换，但要写两段循环；交换版一段循环、顺序天然稳定，是更常用的基准写法。

## 测试用例

```python
def test_solution() -> None:
    solution = Solution()

    def run(nums: list[int]) -> list[int]:
        solution.moveZeroes(nums)
        return nums

    # ---- 官方示例 1 ----
    assert run([0, 1, 0, 3, 12]) == [1, 3, 12, 0, 0]

    # ---- 官方示例 2：单个零 ----
    assert run([0]) == [0]

    # ---- 相邻零（pop+append 写法的翻车用例）----
    assert run([0, 0, 1]) == [1, 0, 0]
    assert run([0, 0, 1, 0]) == [1, 0, 0, 0]

    # ---- 没有零：原样不动 ----
    assert run([1, 2, 3]) == [1, 2, 3]

    # ---- 全是零：原样不动 ----
    assert run([0, 0, 0]) == [0, 0, 0]

    # ---- 零在后半段 ----
    assert run([2, 0, 1]) == [2, 1, 0]
```

提交前用「非零挑出 + 尾部补零」的暴力版随机对照 2000 组，与交换版结果全部一致；另复现了 pop+append 初版在 `[0,0,1]` 上的错误输出 `[0,1,0]`。

## 总结

- 快慢双指针一次遍历：slow 标记非零落位（也是第一个零），非零元素与它交换，O(n) 时间、O(1) 空间；
- 「移动零」反转视角为「收集非零」——不动的元素（零）自然沉底，要动的元素（非零）只做向前交换；
- pop+append 是经典陷阱：中间 pop 引发 O(n²) 搬移，且滑入元素被下标递增跳过，相邻零必错。
