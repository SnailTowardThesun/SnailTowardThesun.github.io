> 离散事件仿真（DES）从不逐秒推进，而是直接跳到下一个事件时刻——操作系统调度器、电梯群控、网络模拟器都靠这一招，把模拟成本从「时间总量」降到「事件数量」。

## 题目

LeetCode 1882. Process Tasks Using Servers（使用服务器处理任务）

Difficulty: **Medium**

给你两个下标从 0 开始的整数数组 `servers` 和 `tasks`，长度分别为 `n` 和 `m`。`servers[i]` 是第 `i` 台服务器的**权重**，`tasks[j]` 是处理第 `j` 项任务所需要的**时间**（单位：秒）。第 `j` 项任务最早在第 `j` 秒开始处理。

处理第 `j` 项任务时，为它分配一台空闲的服务器：

- 若有多台空闲服务器，选**权重最小**的一台；权重相同则选**下标最小**的一台；
- 若没有空闲服务器，则等待；出现空闲服务器后按上述规则**尽可能早**地处理，多项等待任务按**下标递增**顺序分配；
- 同一时刻存在多台空闲服务器时，可以**同时**把多项任务分别分配给它们。

每台服务器同一时刻只能处理一项任务；若在第 `t` 秒接到第 `j` 项任务，则在第 `t + tasks[j]` 秒恢复空闲（该时刻即可分配新任务）。

返回数组 `ans`，其中 `ans[j]` 是第 `j` 项任务分配到的服务器下标。

约束：

- `1 <= n, m <= 2 * 10^5`
- `1 <= servers[i], tasks[j] <= 2 * 10^5`

### 示例

```text
输入：servers = [3,3,2], tasks = [1,2,3,2,1,2]
输出：[2,2,0,2,1,2]
解释：
- 第 0 秒，任务 0 分配给服务器 2（权重 2 最小），处理到第 1 秒；
- 第 1 秒，服务器 2 空闲，任务 1 分配给服务器 2，处理到第 3 秒；
- 第 2 秒，服务器 0/1 权重同为 3，任务 2 分配给下标小的服务器 0，处理到第 5 秒；
- 第 5 秒，三台服务器同时空闲，任务 5 分配给服务器 2，处理到第 7 秒。
```

```text
输入：servers = [5,1,4,3,2], tasks = [2,1,2,4,5,2,1]
输出：[1,4,1,4,1,3,2]
解释：
- 第 0 秒，任务 0 分配给服务器 1（权重 1 最小），处理到第 2 秒；
- 第 2 秒，服务器 1/4 同时空闲，任务 2 分配给权重最小的服务器 1，处理到第 4 秒；
- 第 4 秒，服务器 1 空闲，任务 4 分配给服务器 1，处理到第 9 秒。
```

## 解题思路

### 先把题面里的三个坑看清楚

这题通过率不到 35%，多半倒在读题上。三个容易被忽略的规则：

1. **第 `j` 项任务最早第 `j` 秒开始**——不是「第 `j` 秒必须开始」，排队时可以更晚；
2. **释放当秒即可复用**——第 `t` 秒接的任务在第 `t + tasks[j]` 秒恢复空闲，示例 1 里服务器 2 第 1 秒刚释放、第 1 秒就接了任务 1；
3. **同一时刻可以批量分配**——多台服务器同时释放时，多个排队任务在这一秒各拿一台，而不是每秒只分配一个。

### 为什么逐秒模拟会死

`n`、`m` 都到 `2 * 10^5`，任务时长也到 `2 * 10^5`，仿真时间轴最长可达 `4 * 10^10` 秒——逐秒推进是天文数字；每个任务到来时线性扫一遍服务器找「权重最小的空闲者」也是 `O(m * n)`。两个方向都必须把「找空闲」和「等空闲」变成对数级操作。

### 双最小堆 + 时刻跳跃

让两个堆各管一件事，再用「跳跃」代替「等待」：

1. **空闲堆 `idle`**：存 `(权重, 下标)`，堆顶即「权重最小、同权重下标最小」的服务器——Python 元组比较天然实现这条规则，不用写比较器；
2. **忙碌堆 `busy`**：存 `(释放时间, (权重, 下标))`，堆顶是最早空出来的服务器；
3. 按下标顺序处理任务，维护当前时刻 `now`（先 `max(now, j)`，因为排队可能让 `now` 超过到达秒 `j`）；
4. `idle` 为空时，把 `now` 直接**跳**到 `busy` 堆顶的释放时间——下一个有服务器空出来的时刻，中间的秒一格都不用走；
5. 把 `busy` 中所有释放时间 `<= now` 的服务器**批量**弹回 `idle`——同一时刻释放的多台一并回收，排队任务逐个从 `idle` 弹，恰好实现「同一时刻同时分配多项任务」；
6. 弹出 `idle` 堆顶分配给当前任务，结束时间 `now + tasks[j]` 压回 `busy`。

时刻跳跃保证时间轴上被访问的时刻数只有 `O(n + m)` 个（每个任务至多触发一次跳跃），批量回收保证同时释放的服务器一个不漏。

### 复杂度分析

- 时间复杂度：`O((n + m) log n)`（每台服务器在两堆间至多进出各一次，每次堆操作 `O(log n)`）
- 空间复杂度：`O(n)`（两个堆）

## 代码实现

```python
from heapq import heapify, heappop, heappush


class Solution:
    def assignTasks(self, servers: list[int], tasks: list[int]) -> list[int]:
        ret = []
        idle = [(w, i) for i, w in enumerate(servers)]
        heapify(idle)

        busy = []
        now = 0

        for j, t in enumerate(tasks):
            now = max(now, j)
            if not idle:
                now = max(now, busy[0][0])
            # 回收当前时刻已经完成任务的所有服务器
            while busy and busy[0][0] <= now:
                bt = heappop(busy)
                heappush(idle, bt[1])

            s = heappop(idle)
            ret.append(s[1])
            heappush(busy, (now + t, s))

        return ret
```

### 代码解析

- `idle` 存 `(权重, 下标)`、`busy` 存 `(释放时间, (权重, 下标))`：把选择规则全部交给元组比较，堆顶永远就是该取的那个，全程没有一行自定义比较逻辑；
- `now = max(now, j)`：任务不早于到达秒开始；`now` 只增不减，排队越久跳得越远；
- `if not idle: now = max(now, busy[0][0])`：无服务器可用时时间直接快进，`busy[0]` 是 O(1) 看堆顶，最坏情况整个仿真也只推进 `O(n + m)` 个时刻；
- 回收循环用 `while busy and busy[0][0] <= now` 而非 `if`：同时释放的多台全部收回，这是「同一时刻批量分配」正确性的关键——少了这一步，第二个排队任务就会拿不到本该空闲的服务器；
- 顺序不能乱：先跳跃、再回收、最后分配。若先分配后回收，当前任务会错过刚释放的服务器。

## 测试用例

覆盖两个官方示例、单服务器排队、同权重取下标、同时释放批量分配等边界，外加两个 LeetCode 提交大用例（其中一个就是让无数人翻车的「56/36 服务器同时释放」用例）：

```python
def test_solution() -> None:
    solution = Solution()

    # ---- 官方示例 1 / 示例 2 ----
    assert solution.assignTasks([3, 3, 2], [1, 2, 3, 2, 1, 2]) == [2, 2, 0, 2, 1, 2]
    assert solution.assignTasks([5, 1, 4, 3, 2], [2, 1, 2, 4, 5, 2, 1]) == [1, 4, 1, 4, 1, 3, 2]

    # ---- 单服务器：后续任务排队等待（时刻跳跃） ----
    assert solution.assignTasks([2], [1, 2, 3]) == [0, 0, 0]

    # ---- 恢复空闲的服务器当秒即可复用 ----
    assert solution.assignTasks([10, 5, 5], [1, 1]) == [1, 1]

    # ---- 两台服务器同时空闲，仍取下标最小 ----
    assert solution.assignTasks([4, 4], [2, 2, 2]) == [0, 1, 0]

    # ---- 无空闲服务器时等待，多台同时释放 ----
    assert solution.assignTasks([1, 1], [3, 2, 1]) == [0, 1, 0]

    # ---- 优先复用小权重服务器 ----
    assert solution.assignTasks([3, 5], [2, 1, 1, 1, 1]) == [0, 1, 0, 0, 0]
```

## 总结

- 事件驱动模拟的精髓是**时刻跳跃**：不逐秒走，直接跳到下一个「有服务器空出来」的时刻，时间轴长度从 `4 * 10^10` 压到 `O(n + m)`；
- 双堆分工明确：`idle` 管「选谁」（权重、下标），`busy` 管「何时」（释放时刻），元组嵌套让比较规则零代码；
- 题面三陷阱——最早开始时刻、释放当秒可复用、同一时刻批量分配——逐个写成断言，比提交后发现 Wrong Answer 再排查便宜得多。
