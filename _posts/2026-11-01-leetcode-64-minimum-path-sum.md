> 网格「只能向右或向下」的约束其实是在定义一个 DAG——每个格子恰有两个前驱，按行序双循环天然就是拓扑序。最小路径和、不同路径数、最大正方形，都是同一个 DAG 上的故事。

## 题目

LeetCode 64. Minimum Path Sum（最小路径和）

Difficulty: **Medium**

给定一个包含非负整数的 `m x n` 网格 `grid`，请找出一条从左上角到右下角的路径，使得路径上的数字总和为最小。每一步只能**向下或者向右**移动一步。

约束：

- `m == grid.length`，`n == grid[i].length`
- `1 <= m, n <= 200`
- `0 <= grid[i][j] <= 200`
- 进阶：仅使用 `O(n)` 额外空间

### 示例

```text
输入：grid = [[1,3,1],[1,5,1],[4,2,1]]
输出：7
解释：因为路径 1→3→1→1→1 的总和最小，返回 7。
```

```text
输入：grid = [[1,2,3],[4,5,6]]
输出：12
```

## 解题思路

### 第一眼：这是个 DAG 上的最短路

「只能向右或向下」意味着格子间的依赖关系无环：`(i,j)` 只能由 `(i-1,j)`（上方）和 `(i,j-1)`（左侧）到达。无环 + 依赖单向，DP 一遍扫过就是拓扑序，不需要任何最短路算法。

状态与转移一行写完：

```text
dp[i][j] = grid[i][j] + min(dp[i-1][j], dp[i][j-1])
```

首行只有左邻居、首列只有上邻居，是这条公式的退化情形；答案就是 `dp[m-1][n-1]`。

### 一个真实翻车点：起点分支漏写，负索引替你「背锅」

初版代码里起点判断写成了 `if m == 0 and n == 0`——判断的是**网格尺寸**（恒为假），本意是 `i == 0 and j == 0`（左上角）。这个 bug 之所以隐蔽，是因为它**碰巧不出错**：

1. 起点没走显式分支，落进 `i == 0` 的首行分支，执行 `dp[0][0] = grid[0][0] + dp[0][-1]`；
2. Python 负索引把 `dp[0][-1]` 解释为 `dp[0][n-1]`——行序遍历下它**还没被赋值**，读出初始化的 `0`；
3. 于是 `dp[0][0] = grid[0][0]`，恰好等于正确结果。

零初始化 + 负索引 + 行序计算，三重巧合互相配合把 bug 藏得严严实实——200 组随机对拍都抓不出来（行为碰巧全对）。但它一移植就死：C++/Java 没有 Python 式负索引，`dp[0][-1]` 是真·越界未定义行为；就算留在 Python，把 dp 初值从 0 改成 `inf` 也会立刻翻车。**「碰巧正确」比「明显错误」危险得多**——修复只需把条件改对，让起点走显式赋值。

### 空间的常数优化（可选）

`dp` 整表可以省掉：逐行滚动只需一维 `dp[n]`，甚至直接在 `grid` 上原地写。约束 200×200 下全表也才 4 万项，本题不必优化，但同套路在大网格题（如 120 三角形的自底向上）里值得常备。

### 复杂度分析

- 时间复杂度：`O(m * n)`——每格一次转移
- 空间复杂度：`O(m * n)`，滚动数组可压至 `O(n)`

## 代码实现

```python
class Solution:
    def minPathSum(self, grid: list[list[int]]) -> int:
        m, n = len(grid), len(grid[0])
        dp = [[0] * n for _ in range(m)]
        for i in range(m):
            for j in range(n):
                if i == 0 and j == 0:  # 起点必须显式分支：漏掉会依赖 dp[0][-1] 的负索引巧合
                    dp[i][j] = grid[i][j]
                    continue
                if i == 0:  # 首行：只能来自左侧
                    dp[i][j] = grid[i][j] + dp[i][j - 1]
                elif j == 0:  # 首列：只能来自上方
                    dp[i][j] = grid[i][j] + dp[i - 1][j]
                else:
                    dp[i][j] = grid[i][j] + min(dp[i][j - 1], dp[i - 1][j])

        return dp[m - 1][n - 1]
```

### 代码解析

- `if i == 0 and j == 0` 是唯一需要小心的分支——它看似可省（首行分支「顺便」能算出起点），实则依赖负索引巧合，见上文翻车记录；
- 首行/首列分支没有 `min`：它们各只有一个合法前驱，公式退化为直接相加；
- 按行序双循环天然满足拓扑序，无需显式排序；
- 想要 `O(n)` 空间：把 `dp` 换成一维数组，`dp[j] = grid[i][j] + min(dp[j], dp[j-1])`，`dp[j]`（旧值=上方）与 `dp[j-1]`（新值=左侧）恰好同时可用。

## 测试用例

覆盖官方示例、1×1/单行/单列/全 0、反贪心陷阱、值域上界满网格；期望值经全路径 DFS 暴力验证：

```python
def test_solution() -> None:
    solution = Solution()
    # 官方示例
    assert solution.minPathSum([[1, 3, 1], [1, 5, 1], [4, 2, 1]]) == 7  # 1→3→1→1→1
    assert solution.minPathSum([[1, 2, 3], [4, 5, 6]]) == 12
    # 边界：1x1 / 单行 / 单列 / 全 0
    assert solution.minPathSum([[5]]) == 5
    assert solution.minPathSum([[1, 2, 3]]) == 6
    assert solution.minPathSum([[1], [2], [3]]) == 6
    assert solution.minPathSum([[0, 0], [0, 0]]) == 0
    # 反贪心：每步选相邻较小值会先向右踩进 100 走廊（总和 206），最优 13 在向下那条
    assert solution.minPathSum([[1, 2, 100], [3, 100, 100], [3, 3, 3]]) == 13
    # 负索引陷阱已修：起点显式赋值，不再依赖 dp[0][-1] 恰好为 0
    assert solution.minPathSum([[7, 9], [8, 6]]) == 21
    # 值域上界：200x200 全 200，答案 = (m+n-1)*200
    assert solution.minPathSum([[200] * 200 for _ in range(200)]) == 79800
```

## 总结

- 「只能右/下」的网格题本质是 DAG 最短路：`dp[i][j] = grid[i][j] + min(上, 左)`，按行序一遍扫完；
- 起点分支漏写不会立刻报错——Python 负索引 + 零初始化会替它「碰巧算对」，移植或改初值时才爆雷；显式写 `i == 0 and j == 0` 是免疫写法；
- 测试里专门放一条反贪心用例（局部选小踩进长走廊）与一条值域上界满网格，防止 `min` 漏写、初值污染这类静默错误。
